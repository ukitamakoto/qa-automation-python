# BUG-001: Item total shows floating-point noise for some add orders

| Field | Value |
|---|---|
| Target | SauceDemo · https://www.saucedemo.com |
| User | `standard_user` |
| Severity | Medium: the customer sees a malformed amount at checkout |
| Priority | High |
| Environment | Chromium 156.0.8078.4 and Firefox 157.0 via Playwright 1.64, headless (macOS locally, Ubuntu in CI) |
| Found | 2026-10-14 |
| Reproduced by | `tests/ui/test_checkout.py::test_item_total_is_rounded_to_cents_whatever_the_add_order` (strict xfail) |

## Steps to reproduce
1. Log in with `standard_user` / `secret_sauce`.
2. Add to cart, in this order: Sauce Labs Onesie, Sauce Labs Fleece Jacket, Sauce Labs Bolt T-Shirt, Sauce Labs Bike Light, Sauce Labs Backpack.
3. Cart → Checkout → First Name `Ana`, Last Name `Silva`, Postal Code `8000-123` → Continue.

## Expected
`Item total: $113.95`

## Actual
`Item total: $113.94999999999999`. Tax ($9.12) and Total ($123.07) are correct. The same five products added in catalogue order show `$113.95`.

## Notes
The total appears to be summed in binary floating point in add order and rendered without rounding to cents.
