# BUG-013: Bookings whose legacy e-mail has capitals are dropped by the migration

| Field | Value |
|---|---|
| Target | Booking migration · `sql/migration.sql` |
| Step | `INSERT INTO bookings ... JOIN guests` |
| Severity | High: data loss; 2 of 12 bookings disappear without an error |
| Priority | High |
| Environment | SQLite 3.50.4 (Python stdlib), in-memory database |
| Found | 2026-10-14 |
| Reproduced by | `tests/sql/test_migration.py::test_check_returns_no_rows[every_legacy_booking_is_migrated]` (strict xfail) |

## Steps to reproduce
1. Load `sql/legacy.sql` and run `sql/migration.sql`.
2. Run `sql/checks/every_legacy_booking_is_migrated.sql`.

## Expected
No rows: all 12 legacy bookings have a migrated row.

## Actual
Two rows: legacy bookings 4 (`Rafael.Costa@Example.com`) and 7 (`ELISA.RAMOS@EXAMPLE.COM`) are missing. Their guests exist, because guests are stored with `lower(email)`, but the bookings join on the raw legacy e-mail, so the inner join finds no match and drops them.

## Suggested fix
Join on `g.email = lower(l.email)`, and compare the row counts before and after the migration.
