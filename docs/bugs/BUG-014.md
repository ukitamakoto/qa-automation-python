# BUG-014: The migration loses a cent on some prices

| Field | Value |
|---|---|
| Target | Booking migration · `sql/migration.sql` |
| Step | `CAST(CAST(l.totalprice AS REAL) * 100 AS INTEGER)` |
| Severity | High: wrong money values; totals no longer reconcile with the legacy system |
| Priority | High |
| Environment | SQLite 3.50.4 (Python stdlib), in-memory database |
| Found | 2026-10-14 |
| Reproduced by | `tests/sql/test_migration.py::test_check_returns_no_rows[totals_are_preserved_to_the_cent]` (strict xfail) |

## Steps to reproduce
1. Load `sql/legacy.sql` and run `sql/migration.sql`.
2. Run `sql/checks/totals_are_preserved_to_the_cent.sql`.

## Expected
No rows: every `total_cents` equals the legacy price, so `19.99` becomes `1999`.

## Actual
Three rows: `19.99` becomes `1998`, `64.10` becomes `6409` and `8.20` becomes `819`. In binary floating point, `19.99 * 100` is `1998.9999...`, and casting to an integer truncates it instead of rounding it.

## Suggested fix
Convert the text price without floating point, for example `CAST(replace(totalprice, '.', '') AS INTEGER)` when there are always two decimals, or `ROUND(...)` before the cast.
